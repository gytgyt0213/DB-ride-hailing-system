# 打车系统

## 一、系统概述

一个简化的城市网约车（打车）平台。乘客通过平台发起叫车请求，平台把订单派给附近司机，司机完成接驾和行程。本作业聚焦“乘客下单—平台派单—司机接单—行程执行—订单状态追踪—计价”这条核心链路，不要求实现在线支付、退款、售后等复杂功能。

## 二、系统涉及主体

| 主体 | 说明 |
| --- | --- |
| 平台管理员 | 维护平台基础数据、管理司机与车辆账号、处理异常订单。 |
| 乘客 | 注册登录，选择上车点和下车点，发起叫车，查看订单状态。 |
| 司机 | 注册登录，上线接单，执行行程，结束行程。 |
| 车辆 | 属于某位司机，记录车牌号、车型、座位数、运营状态等。 |
| 订单 | 一次叫车或行程的凭证，记录上下车点、状态、金额和时间。 |
| 计价规则 | 定义起步价、里程单价、时长单价等，用于计算车费。 |
| 常用地址 | 乘客保存的家、公司等常用上车或下车地点。 |
| 评价（选做） | 乘客对行程和司机的评分与评价。 |

## 三、系统需求

### 核心需求（必做，按重要程度排序）

1. 乘客下单：乘客选择上车点、下车点（可复用常用地址）和车型，发起叫车请求，生成“待接单”订单。
2. 平台派单与司机接单：平台根据司机在线状态、车辆类型和所在区域，把订单派给合适的司机；司机可以接单或拒单。
3. 司机行程执行：司机接单后前往上车点，确认乘客上车、开始行程，到达目的地后结束行程。
4. 订单状态实时追踪：乘客可实时查看订单状态流转，如“待接单→已接单→司机已到达→行程中→已完成→已取消”，并记录各状态节点的时间。
5. 订单计价：根据起步价、里程和时长等规则自动计算车费；不要求在系统内完成真实在线支付。
6. 司机与车辆管理：管理员维护司机和车辆档案；司机可上线、下线，只有车辆处于可运营状态时才能接单。
7. 账号与角色管理：管理员、司机、乘客使用不同账号登录，并按角色区分可访问和可操作的功能。

### 非核心需求（选做，按重要程度排序）

- 司机资质与证照审核、到期提醒
- 车辆实时位置展示与行程轨迹回放
- 预约用车（指定用车时间）
- 拼车或顺风车（一个订单涉及多名乘客，或司机连续接多个订单）
- 优惠券、红包或促销活动
- 乘客评价与司机服务分
- 区域供需统计、热力图和订单量报表

说明：支付、退款、售后等涉及资金和复杂流程的功能，不作为本次作业要求。
